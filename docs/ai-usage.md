# AI 활용 및 고도화 · Use of AI Tools

## 활용한 AI 도구 및 활용 범위

| 단계 | 도구 | 활용 범위 |
|---|---|---|
| 기획 · 설계 | ChatGPT, Google AI Studio | 유학생 행정 정보 정리, 기능 명세 초안 도출 |
| UI/UX 설계 | Claude Design | 다국적 사용자를 고려한 화면 설계 |
| 코드 작성 · 리팩토링 | Cursor, GitHub Copilot, OpenAI Codex, **Claude Code** | 반복 작업 자동화, API 연동, 인증 구조(Supabase Auth, JWT), 통합 테스트, 배포 설정 |
| 제품 내 탑재 | OpenRouter(1차) + Gemini(폴백) | AI 어시스턴트 응답 생성, 지식베이스 임베딩·검색(RAG, 팀 내부 명칭 **OKF**: Open Knowledge Framework), 스크랩한 공지·학식 메뉴의 실시간 번역 |

제품에 실제로 탑재된 생성형 AI는 위 마지막 행뿐이다. 추천 엔진(수강·비교과)은 모델을 호출하지 않는 결정론적 규칙 기반 로직이며, README §1.4에 "✅ AI"가 아닌 "✅ 개인화 자동 추천"으로 명시했다 — 실제로 모델을 호출하지 않는 기능을 AI로 표기하지 않기 위함이다.

가장 많이 사용한 도구는 **Claude Code**로, `main` 브랜치에 반영된 커밋 중 62건이 Claude Code와의 공동 작업(Co-Authored-By)으로 기록되어 있으며, 인증 구조 개편·RAG 검색·배포 설정·회귀 버그 수정 대부분이 이 방식으로 진행되었다.

## OKF(Open Knowledge Framework) 성능 검증

"AI가 지식베이스를 참고해서 답한다"는 주장을 수치로 검증하기 위해 자체 벤치마크(`backend/benchmark/`)를 구축했다. 동일한 모델·동일한 시스템 프롬프트로, **OKF가 검색한 컨텍스트를 주입한 경우**와 **주입하지 않은 경우**(non-OKF baseline)를 같은 40개 질문에 대해 비교한다. 평가자는 답변 생성 모델과 반드시 다른 벤더의 모델을 쓰도록 하드코딩되어 있다(자체 채점 방지). 40문항 실행 결과(`results/2026-08-05T18-03-51-703Z.md`, 답변 모델 `google/gemini-2.5-flash`, 평가 모델 `openai/gpt-4o-mini`):

| 지표 | OKF 적용 | 미적용 | 차이 |
|---|---:|---:|---:|
| 커버된 질문 정확도 | 91.4% | 32.8% | +58.6pt |
| PNU 특화도 | 77.6% | 36.2% | +41.4pt |
| 환각(hallucination) 비율 (낮을수록 좋음) | 2.8% | 26.3% | -23.5pt |
| 모르는 내용을 정직하게 인정 | 100% | 22.2% | +77.8pt |

질문 세트는 세 종류로 구성된다: KB에 답이 있는 질문(31개, 검색 후 실제로 활용하는지 측정), KB에 답이 없는 질문(9개, 지어내지 않고 모른다고 답하는지 측정), 그리고 일반 모델이 자신 있게 틀리는 질문(3개, 예: "국제학생은 주 20시간까지 근무 가능"이라는 널리 퍼진 정보가 실제 PNU 기준과 다름을 보여주는 사례). 모든 정답 근거는 실제 KB 문서에서 그대로 인용해 채점 기준을 검증 가능하게 만들었다.

## AI 생성 코드의 검증 · 수정 방식

AI가 작성한 코드를 그대로 반영하지 않고, 아래 세 단계로 검증했다.

**1. 실제 실행 검증** — 코드 작성 후 반드시 실행하여 확인했다. 예: RAG 임베딩 제공자를 Gemini에서 OpenRouter로 전환한 뒤, 유사도 임계값(0.65)이 새 임베딩 모델에서 전혀 맞지 않아 검색 결과가 0건으로 나오는 것을 실측 데이터(주제 내 0.376–0.692, 주제 외 0.137–0.262)로 재측정하여 0.32로 수정했다. 코드만 보고 넘어갔다면 발견하지 못했을 문제였다.

**2. 뮤테이션 테스트로 테스트 자체를 검증** — "테스트가 통과한다"만으로는 부족하다고 판단해, 핵심 로직 12곳에 대해 의도적으로 코드를 손상시킨 뒤 테스트가 실제로 실패하는지 확인하는 방식(mutation testing)을 사용했다. 예: 알림(공지) 중복 발송 방지 로직에서, 병합 로직을 일부러 제거했을 때 테스트가 실패하는지 확인 → 실패하지 않으면 테스트를 다시 작성.

**3. 다중 에이전트 교차 검증(비자·졸업요건 등 고위험 정보)** — 학생에게 법적·행정적으로 잘못된 정보를 전달하면 실질적 피해로 이어지는 항목(시간제 취업 허가, 졸업 요건, 국제학생 어학 요건)은 AI가 작성한 한국어 요약을 원문(법무부 시행세칙, 학과 교육과정표)과 대조하는 별도의 검증 단계를 거쳤다. 1차 검증에서 "국제학부 학생은 영어 요건 대상에서 제외된다"는 문장이 원문과 반대(실제로는 영어 요건 **대상**)임을 발견해 반려하고 재작성했다.

**직접 발견하고 수정한 대표 사례:**

- README에 "과목 추천: ✅ AI"로 표기되어 있었으나 실제로는 모델을 호출하지 않는 규칙 기반 엔진임을 코드 대조로 확인 → 표기 수정
- 알림 발송 로직을 "공지 1건당 1회 발송"으로 작성할 경우 시험 기간 등 공지가 몰리는 시간에 반복 알림이 발생함을 사전에 인지 → 15분 주기당 1회로 통합 발송하도록 설계 변경
- OpenRouter의 특정 모델(anthropic/claude-3.5-sonnet)이 서비스 종료되어 매 요청마다 404 후 대체 모델로 전환되고 있었음을 로그 분석으로 발견 → 설정값 교체 및 재발 방지용 점검 스크립트(`npm run check:models`) 추가

## 결론

AI 도구는 코드 작성 속도를 높이는 데 크게 기여했으나, **AI가 작성한 코드를 검증 없이 반영한 사례는 없다.** 특히 학생에게 직접 노출되는 법적·학사 정보는 원문 대조 없이 신뢰하지 않는 것을 원칙으로 삼았다.
